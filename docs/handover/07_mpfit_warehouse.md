# МПФИТ и склад (фулфилмент)

Склад Market Partners в Чехове работает в внешней WMS **МПФИТ** (app.mpfit.ru).
Вокруг неё построены два наших модуля:

1. **mpfit-dashboard** (`mpfit_dash/`) — аналитика и учёт ФФ: заказы, скорость,
   услуги, финансы, сотрудники, клиенты ФФ и их продажи, «Упаковка КИЗ», ТСД.
2. **Своя WMS** (`backend/routers/wms.py` + `frontend/wms.*`, спецификация
   `docs/wms_spec.md`) — задел на замену МПФИТ («часто всё падает»). Живёт
   внутри основного бэкенда (`/wms`, `/api/wms/*`).

## 1. mpfit-dashboard (`mpfit_dash/`)

**Render:** Root Directory `mpfit_dash`, старт `uvicorn app:app --host 0.0.0.0 --port $PORT`,
health `/health`, Build Filters `mpfit_dash/**`, `backend/db.py`, `docs/mpfit_api/**`.
База — общий Postgres, `DB_SCHEMA=mpfit` (локально SQLite через `SQLITE_PATH`).
**Один воркер** — очередь заданий ТСД хранится в памяти процесса.

**Переменные:** `DATABASE_URL`, `DB_SCHEMA`, `MPFIT_TOKEN` (токен фулфилмента
от поддержки МПФИТ — видит всех селлеров), `DASH_USER`, `DASH_PASSWORD`
(basic-auth; без него сервис отвечает 503), `KIZ_PIN`, `KEYS_SECRET` (шифрование
ключей клиентов; если нет — выводится из `DASH_PASSWORD`, тогда при смене
пароля ключи надо ввести заново), `TG_BOT_TOKEN`, `TG_CHAT_ID`.

| Файл | Роль |
|---|---|
| `app.py` | все эндпоинты, авторизация, очередь ТСД, разбор xlsx поставок |
| `store.py` | схема БД и CRUD |
| `sync.py` | фоновая синхронизация МПФИТ → БД, Telegram-алерты |
| `mpfit_client.py` | клиент МПФИТ (`https://app.mpfit.ru/api`, Bearer, 120 запр/мин, курсор `last_id`) |
| `clients_mp.py` | ключи WB/Ozon клиентов ФФ (Fernet), сбор их заказов, сверка остатков |
| `bank.py` | разбор выписки Альфа-банка, классификация операций |
| `report.py` | расчёты: сводка, по дням, скорость, услуги, клиенты, финансы (P&L, ДДС, налог 7%), план/факт, зарплата |
| `static/index.html` | закрытый дашборд: Пульс, Заказы, Скорость, Услуги, Клиенты, Финансы, План/факт, Сотрудники, Продажи клиентов |
| `static/kiz.html` + `kiz-parse.js` | «Упаковка КИЗ» (публичная страница) |

### Эндпоинты (кратко)

- **Служебные:** `/health`, `/api/status`, `POST /api/sync`, `POST /api/probe`
  (прокси к МПФИТ только на чтение, белый список), `POST /api/arrivals/create`
  (заявка на приёмку в МПФИТ — **запись в боевую систему**, нужен `confirm:true`,
  защита от дублей).
- **Заказы:** `/api/summary`, `/api/daily`, `/api/speed`, `/api/services`
  (отгружено без услуги «Отгрузка FBS» — её надо проставлять, иначе услуга не
  начислится), `/api/clients`.
- **Финансы:** `/api/finance`, `/api/planfact`, `/api/plan`, `/api/ledger`
  (CRUD журнала: expense/investment/funding/client_payment/other_income;
  оплата cash/rs/personal), `/api/invoices` (+ отметка оплаты), `/api/recurring`.
- **Сотрудники:** `/api/staff?month=` (табель и начисления: смены × ставка +
  единицы × сдельная ставка; отгрузки дня делятся между вышедшими),
  `POST /api/staff`, `POST /api/shifts`. Выплата — запись в ledger с `category=ФОТ`.
- **Банк:** `POST /api/bank/import` (xlsx Альфы), `/api/bank`.
- **Снимки остатков** по контрагентам каждые 30 мин, 90 дней («бэкап МПФИТ»):
  `/api/stocks/snapshot`, `/refresh`, `.xlsx`.
- **Клиенты ФФ и их маркетплейсы:** `/api/mpkeys` (ключи WB/Ozon клиента
  вводятся в интерфейсе), `/api/mpkeys/{id}/wbdiag` («почему на WB нет остатка»),
  `/api/mpkeys/{id}/stock_recon` (сверка остатков МПФИТ ↔ склады продавца WB),
  `/api/mpsales` (продажи клиента, `days=0` — с даты старта работы, наша доля
  FBS), `/api/mpsales/start`, `/api/mpsales/warehouse` (наш/чужой склад).

### Фоновые процессы

- `sync.loop()` — каждые 5 мин (90 с при очереди проверки услуг): компании,
  заказы, счета, хранение, снимок остатков (≤ раз в 30 мин), проверка услуги
  «Отгрузка FBS», алерт в Telegram.
- `clients_mp.loop()` — раз в 3 ч: заказы клиентов ФФ (WB statistics, запасной
  путь marketplace-api FBS; Ozon FBO/FBS).

### Знания по МПФИТ

- API: `docs/mpfit_api/openapi.yaml` (v1.4.0). Настроек передачи остатков на
  маркетплейсы в API **нет** — только в интерфейсе МПФИТ. История: у клиента
  «Марципан» остатки не уходили на WB, потому что в МПФИТ была снята галочка
  «управление остатками».
- Заявка на приёмку файлом: первая строка — «Код товара, Кол-во, Примечание к
  товару», только xlsx; код товара = артикул.
- Настройки отгрузки (`Настройки → Склад → Отгрузка`): поставки WB FBS 2 раза в
  день (10:00 и 15:00), «назначать дату "сегодня" до» — 15:00.
- На каждый отгруженный FBS-заказ должна быть проставлена услуга «Отгрузка FBS»
  (галочка) — иначе не начислится; дашборд это проверяет.

## 2. «Упаковка КИЗ» — главная рабочая страница склада

Адрес из РФ: **https://marketpartners.ru/kiz** (через VPS). PIN сейчас отключён.

**Зачем:** товар с КИЗ «Честного знака» переупаковывается на складе — КИЗ
нужно продублировать на внешнюю этикетку вместе со штрихкодом и сроком годности.

**Процесс:**
1. Скан КИЗ (DataMatrix) и штрихкода товара (EAN-13 / Code128) — в любом порядке.
2. Срок годности (по приоритету): из самого КИЗ (AI 17) → «Честный знак»
   (`/crpt/mobile/check` через VPS) → загруженный файл поставки / ручной ввод по GTIN.
3. Товар (название, артикул): из снимка остатков МПФИТ, если нет — из файла поставки.
4. Как только есть КИЗ + ШК + срок — **печать сразу** (без кнопки), запись в журнал.
   Держит только несовпадение штрихкода с товаром. Повторный КИЗ печатается с
   предупреждением.
5. Этикетка 58×40: DataMatrix, короткое название («тип / линейка», до 58 симв.),
   артикул, «Годен до», штрихкод.

**Режимы** (выбор в шапке, хранится в браузере):
- «Печать с этого компьютера»;
- **«ТСД: скан → печать на станции»** — Android-ТСД сканирует, задание уходит
  на станцию (`POST /api/kiz/job`), ТСД видит статус «напечатано»;
- **«Станция печати для ТСД»** — компьютер с термопринтером забирает задания
  долгим опросом (`GET /api/kiz/jobs?wait=25`), не тормозит в фоновой вкладке.

**Ещё на странице:** история печати с кнопкой «Перепечатать»; «Сроки годности
из поставки» (загрузка xlsx поставки: ЕАН + Срок годности [+ наименование,
партия, артикул, количество]); «Сборка по поставке» (план из файла / собрано —
уникальные КИЗ с начала поставки / осталось).

**Печать без окна:** Chrome с флагом `--kiosk-printing`; Firefox —
`about:config` → `print.always_print_silent=true` + бумага принтера 58×40 по
умолчанию (CUPS: `lpadmin -p XprinterV3 -o PageSize-default=w164h113`) и
prefs `print.printer_XprinterV3.print_paper_*`. В Firefox на Linux тихая печать
сейчас ещё мелкая — см. `09_open_tasks.md`.

**Таблицы:** `kiz_expiry` (срок/товар/артикул/партия по GTIN), `kiz_log`
(журнал этикеток), `kiz_supply` (строки поставок — план сборки).

## 3. Своя WMS (MVP, `/wms`)

- Авторизация своя: cookie `wms_session`, роли `staff` и `client` (клиент видит
  только свой `client_id`). Первый админ — из `WMS_ADMIN_LOGIN`/`WMS_ADMIN_PASSWORD`
  (если не заданы — захардкоженные значения по умолчанию, **сменить**).
- Принципы: остаток = сумма append-only журнала `wms_moves`; каждая операция
  сразу пишет `wms_billing` со снимком цены; `client_id` во всех таблицах.
- **Сделано:** клиенты и тарифы, SKU и штрихкоды, поставки (ASN) с коробами и
  паллетами + этикетки + импорт xlsx, приёмка (паллетой/поштучно/с сортировкой)
  с партиями и сроками, остатки и движения, отгрузка FBS (ручной ввод, списание
  FIFO), возврат и корректировка, начисления, суточное хранение (30 дней
  бесплатно, далее по возрасту партии), фоновый `_wms_storage_loop` раз в час.
- **Не сделано** (есть в спецификации): ячейки/putaway, резервы и волны, пик-батчи,
  scan-to-pack, поллинг заказов WB/Ozon, расхождения с фото, пересчёты, инвойсы,
  Telegram-уведомления. Отгрузка в спеке — FEFO, сделана FIFO.
- Тариф по умолчанию (`DEFAULT_TARIFF`): сборка по ступеням объёма упаковки,
  приёмка трёх видов, возврат, КИЗ, хранение по «эквиваленту короба» 77 л.

## 4. Клиенты фулфилмента

- «Марципан», «Субоч» (твёрдые шампуни, несколько юрлиц), клиенты с интимными
  товарами и др. Для части клиентов есть их ключи WB/Ozon в mpfit-dashboard
  (вкладка «Продажи клиентов»): мы видим их заказы, наши FBS-отгрузки, долю
  нашего склада, сверку остатков.
- Для клиентов делались: виртуальные склады WB «ФФ Чехов — СЦ …» (Москва/МО),
  раскладка товара по стеллажам G–L по контрагентам и спросу, отчёты «спрос и
  остатки», заявки на приёмку со сроками, допсоглашения по тарифам упаковки и
  маркировки (документы — у владельца).

## 5. Учёт ФФ — что важно

- Налог 7% к удержанию с выручки (TAX_RATE в store.py).
- Расходы, оплаченные личными средствами владельцев, учитываются как «долг
  владельцам» (вернуть).
- Входящий остаток на РС до начала работы — не деньги бизнеса.
- С 19.10 основной учёт затрат ФФ владелец вёл в Excel; дашборд — для пульса и
  зарплаты. Ставки сотрудников (выход, сдельно за FBS, приёмка, паллеты,
  упаковка) — заданы в карточках сотрудников, суммы владелец передаёт отдельно.
